# Mini RPC（基于 Netty 的简化 RPC 框架）

> 一个面向面试与工程实践的学习型项目：从 0 到 1 手写可运行的简化 RPC 框架，并在过程中沉淀可复用的架构与排障方法。

## 1. 项目定位

Mini RPC 的目标不是“造一个功能最多的轮子”，而是用可理解、可演进的方式，把后端基础设施中的关键能力串起来：

- 网络通信（Netty）
- 请求协议（RpcRequest / RpcResponse）
- 编解码与序列化
- 客户端动态代理
- 服务注册与发现
- 负载均衡与容错

该项目适合：

- 计算机相关专业在读，准备后端实习/校招
- 已会 Java/Spring，但希望补齐分布式底层能力
- 想把“会用框架”升级为“会设计框架”

## 2. 你将学到什么

- 如何把“本地方法调用”抽象为“远程调用语义”
- 如何设计最小可用的 RPC 协议
- 为什么高性能网络通信通常选择 Netty
- 动态代理在 RPC 中如何解耦业务与通信
- 注册中心、负载均衡、容错在分布式中的工程意义
- 如何从“能跑”走向“可观测、可排障、可扩展”

## 3. 目标架构（模块划分）

固定模块结构如下：

```text
mini-rpc/
  rpc-core       # 协议定义、编码解码、序列化抽象
  rpc-client     # 客户端调用能力、动态代理、负载均衡
  rpc-server     # 服务暴露、请求处理、服务执行
  rpc-registry   # 注册中心与服务发现
  rpc-demo       # 演示模块与集成验证
```

## 6. 开发与学习原则

- 每新增一个模块，都回答三个问题：它解决什么问题、没有它会怎样、为何是现在实现
- 每个阶段都提供可验证结果（可运行、可观测、可解释）
- 每次演进都保留“面试可讲版本”：背景、方案、权衡、结果、复盘
- 优先做最小闭环，再迭代完善（避免一开始过度设计）

## 7. 面试讲述模板（项目总览版）

可以用下面这段进行高频场景的项目介绍：

> 这是一个我从零实现的简化 RPC 框架，核心目标是完整走通一次远程调用链路，包括协议设计、序列化、Netty 通信、动态代理、注册发现、负载均衡和容错。项目按模块拆分为 core/client/server/registry/demo，采用分阶段迭代方式推进。这个项目让我能解释清楚 Dubbo 类框架的核心思想，不只是会用，而是理解其底层原理和工程权衡。
