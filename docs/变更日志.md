## 2026-03-22

### 阶段：Day3（连接复用与超时机制）

变更内容：

- 客户端引入请求映射表 `requestId -> CompletableFuture`
- 客户端响应处理器改为按 `requestId` 定位并完成对应请求
- 客户端发送逻辑改为连接复用，不再每次请求新建 Netty 连接
- 增加请求超时控制与连接断开时的批量失败回填
- 增加连接断开标记与重连重试策略
- 增加客户端调用统计与并发演示入口 `ClientLoadBootstrap`

影响范围：

- rpc-client 核心通信实现
- rpc-client 响应处理器
- rpc-demo 客户端启动流程
- rpc-demo 并发验证入口

验证结果：

- `mvn clean package -DskipTests` 构建成功
- 服务端启动后客户端调用成功并输出 `rpc result: hello mini-RPC`
- 请求链路日志可见 `requestId` 与 `methodName` 对应关系
- 并发演示可输出请求统计（total/success/failed/timeout）

## 2026-04-16

### 阶段：Day6（Watcher + 本地缓存）

变更内容：

- 为 `rpc-registry` 模块增加 `curator-recipes` 依赖，用于接入 `CuratorCache`
- 在 `ZookeeperRegistryCenter` 中新增 `serviceName -> List<ServiceInstance>` 本地缓存
- `discover(serviceName)` 升级为缓存优先：首次拉取 ZooKeeper 数据并初始化缓存，后续优先读取 JVM 本地缓存
- 为每个服务路径启动 `CuratorCache` watcher，服务实例上下线时自动刷新本地缓存
- 新增 `ZookeeperRegistryCenterTest`，基于 Curator 内嵌 ZooKeeper 验证 Day6 缓存刷新行为
- 新增 `Day6RpcSmokeTest`，基于内嵌 ZooKeeper 跑通真实 `RpcServer -> RpcClient` 调用链
- 关闭注册中心时同步关闭 watcher、清理缓存，并补充 Day6 学习型注释与说明文档

影响范围：

- `rpc-registry` 模块依赖与 `ZookeeperRegistryCenter`
- `rpc-registry` Day6 集成测试
- `rpc-demo` Day6 端到端烟雾测试
- `rpc-client` 服务发现相关注释
- `rpc-demo` 客户端入口注释
- docs Day6 文档与阶段说明

验证结果：

- `mvn -pl rpc-client,rpc-registry,rpc-demo -am package -DskipTests` 构建成功
- `mvn -pl rpc-registry -Dtest=ZookeeperRegistryCenterTest test` 通过
- `mvn -pl rpc-demo -am -Dtest=Day6RpcSmokeTest -DfailIfNoTests=false test` 通过
- 客户端服务发现逻辑已切换为“首次拉取 + 本地缓存 + watcher 自动刷新”
- 代码诊断未发现新增语法或类型错误
