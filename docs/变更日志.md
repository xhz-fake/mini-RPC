## 2026-03-21

### 阶段：Day2（Netty 通信改造）

变更内容：

- 客户端通信从 Socket 直连改为 Netty Bootstrap
- 服务端通信从 ServerSocket 监听改为 Netty ServerBootstrap
- 新增 Netty 编解码处理器并保留原有 RpcRequest/RpcResponse 协议
- 跑通 hello 远程调用，输出 `rpc result: hello mini-RPC`

影响范围：

- 根工程与 core/client/server 的 Maven 依赖
- rpc-core 编解码目录
- rpc-client 与 rpc-server 通信实现

验证结果：

- `mvn clean package -DskipTests` 构建成功
- 服务端启动成功并监听 9000 端口
- 客户端调用成功并收到预期响应

## 2026-03-22

### 阶段：Day3（连接复用与超时机制）

变更内容：

- 客户端引入请求映射表 `requestId -> CompletableFuture`
- 客户端响应处理器改为按 `requestId` 定位并完成对应请求
- 客户端发送逻辑改为连接复用，不再每次请求新建 Netty 连接
- 增加请求超时控制与连接断开时的批量失败回填
- 增加连接断开标记与重连重试策略
- 增加客户端调用统计与并发演示入口 `ClientLoadBootstrap`

影响范围：

- rpc-client 核心通信实现
- rpc-client 响应处理器
- rpc-demo 客户端启动流程
- rpc-demo 并发验证入口

验证结果：

- `mvn clean package -DskipTests` 构建成功
- 服务端启动后客户端调用成功并输出 `rpc result: hello mini-RPC`
- 请求链路日志可见 `requestId` 与 `methodName` 对应关系
- 并发演示可输出请求统计（total/success/failed/timeout）

## 2026-03-25

### 阶段：Day4（服务注册与发现）

变更内容：

- 在 `rpc-registry` 模块中补齐 `ServiceInstance`、注册中心接口和本地文件注册中心实现
- 客户端从固定 IP 直连升级为按服务名发现实例，并引入最小可用随机负载均衡
- 客户端增加最小失败重试能力，失败时可切换到其他实例重试
- 服务端启动时自动注册自身，关闭时注销实例
- demo 启动入口与部署文档升级为 Day4 场景

影响范围：

- rpc-registry 模块
- rpc-client 服务发现与连接管理
- rpc-demo 启动流程与并发演示入口
- README 与部署/架构文档

验证结果：

- `mvn -pl rpc-client,rpc-server,rpc-registry,rpc-demo -am package -DskipTests` 构建成功
- 服务端启动后可在本地注册中心文件中看到已注册实例
- 客户端无需写死地址即可发现服务并成功完成调用
