# Mini RPC 部署指南

## 1. 文档目标

本指南只负责一件事：让零经验同学也能把 Mini RPC 在本地跑起来。  
架构原理请看《架构设计白皮书》，技术取舍请看《技术选型最佳实践》。

## 2. 适用范围

- Windows 10/11（优先）
- macOS/Linux（命令同理）
- JDK 17+
- Maven 3.9+

## 3. 前置环境检查

### 3.1 安装 JDK

```bash
java -version
```

预期：输出版本号且主版本不低于 17。

### 3.2 安装 Maven

```bash
mvn -version
```

预期：输出 Maven 版本信息，并识别到本机 Java 环境。

### 3.3 获取项目代码

```bash
git clone <你的仓库地址>
cd mini-RPC
```

## 4. ZooKeeper 准备

Day5 之后，默认启动链路依赖 ZooKeeper 作为注册中心，所以在启动服务端和客户端前，需要先准备好本地 ZooKeeper。

### 4.1 确认 ZooKeeper 安装目录

Windows 常见目录示例：

- `D:\dev\zookeeper`
- `D:\Program Files\zookeeper`
- `C:\tools\zookeeper`

如果你忘了装在哪，可以在 PowerShell 中搜索：

```powershell
Get-ChildItem -Path D:\,C:\ -Directory -Recurse -ErrorAction SilentlyContinue |
  Where-Object { $_.Name -match 'zookeeper|apache-zookeeper' } |
  Select-Object -ExpandProperty FullName
```

### 4.2 初始化配置

进入 ZooKeeper 安装目录后，确认存在：

- `conf\zoo_sample.cfg`
- `bin\zkServer.cmd`

如果还没有正式配置文件，执行：

```powershell
Copy-Item .\conf\zoo_sample.cfg .\conf\zoo.cfg
```

### 4.3 启动 ZooKeeper

```powershell
.\bin\zkServer.cmd
```

预期：控制台输出 `binding to port 0.0.0.0/0.0.0.0:2181` 或类似内容，表示单机模式已启动。

### 4.4 快速自检

```powershell
.\bin\zkCli.cmd -server 127.0.0.1:2181
```

进入客户端后执行 `ls /`，能正常返回节点列表即可。

## 5. 第一次启动（推荐流程）

### 5.1 拉取依赖并编译

```bash
mvn clean package -DskipTests
```

预期：所有模块编译成功，出现 `BUILD SUCCESS`。

### 5.2 使用 IDEA 导入项目（新手必做）

1. 打开 IDEA，点击 `Open`，选择项目根目录 `mini-RPC`。  
2. 等待右下角 Maven 导入完成。  
3. 打开 `File -> Project Structure -> Project`，确认 `Project SDK = JDK 17`。  
4. 打开 `Settings -> Build, Execution, Deployment -> Build Tools -> Maven`，确认 Maven 可用。  
5. 在右侧 Maven 面板执行一次 `Lifecycle -> clean`、`Lifecycle -> package`。  

预期：`package` 阶段成功，且 `rpc-core/rpc-client/rpc-server/rpc-demo` 都编译通过。

### 5.3 在 IDEA 启动服务端

1. 打开文件 `rpc-demo/src/main/java/com/minirpc/demo/ServerBootstrap.java`。  
2. 点击 `main` 方法左侧绿色三角，选择 `Run 'ServerBootstrap.main()'`。  
3. 看到控制台输出 `server started at 127.0.0.1:9000` 和 `service registered: ...` 即成功。  
4. 如果控制台出现 ZooKeeper 连接成功日志，说明服务实例已经注册到注册中心。  

### 5.4 在 IDEA 启动客户端

1. 保持服务端窗口不要关闭。  
2. 打开文件 `rpc-demo/src/main/java/com/minirpc/demo/ClientBootstrap.java`。  
3. 点击 `main` 方法左侧绿色三角，选择 `Run 'ClientBootstrap.main()'`。  
4. 客户端控制台输出两次 `hello mini-RPC-*` 即调用成功。  

### 5.5 Day7 策略切换启动方式

如果你想直接验证 Day7 的序列化抽象和负载均衡切换，可以在客户端 Run Configuration 或命令行中增加 JVM 参数：

```text
-Drpc.serializer=json
-Drpc.loadbalancer=round_robin
```

含义：

- `rpc.serializer=json`：切换为 JSON 序列化
- `rpc.loadbalancer=round_robin`：切换为轮询负载均衡

如果不传，项目会回退到默认策略。

### 5.6 纯命令行启动（可选）

如果你暂时不想在 IDEA 配置 Run Configuration，可以使用命令行：

启动服务端：

```bash
java -cp "rpc-core\target\classes;rpc-registry\target\classes;rpc-server\target\classes;rpc-demo\target\classes" com.minirpc.demo.ServerBootstrap
```

新开终端启动客户端：

```bash
java -Drpc.client.timeout.seconds=120 -cp "rpc-core\target\classes;rpc-registry\target\classes;rpc-client\target\classes;rpc-demo\target\classes;C:\Users\17798\.m2\repository\io\netty\netty-all\4.1.65.Final\netty-all-4.1.65.Final.jar" com.minirpc.demo.ClientBootstrap
```

预期：客户端输出两次 `hello mini-RPC-*`。

## 6. 最小自检清单

- `mvn clean package -DskipTests` 成功
- ZooKeeper 成功启动并监听 `2181`
- 服务端输出 `server started at 127.0.0.1:9000`
- 服务端输出 `service registered: ...`
- 客户端输出两次 `hello mini-RPC-*`
- 服务端不断开时，客户端可重复调用成功
- 改动 `HelloServiceImpl` 返回值后，重新运行能看到新结果
- 传入 `-Drpc.serializer=json` 后，调用链路仍然成功
- 传入 `-Drpc.loadbalancer=round_robin` 并启动多实例后，请求可按轮询分发

## 7. 常见启动失败与快速处理

- 依赖下载失败：检查网络与 Maven 镜像配置
- 端口占用：修改启动端口或结束占用进程
- Java 版本不匹配：统一为 JDK 17+
- ZooKeeper 启动失败：先检查 `conf\zoo.cfg` 是否存在，再确认 `2181` 端口未被占用
- 主类找不到：确认模块名、包名、启动类全限定名
- IDEA 无法识别 Maven 项目：右键根 `pom.xml` 执行 `Add as Maven Project`
- IDEA 运行时报 `ClassNotFoundException`：先执行一次 `mvn clean package -DskipTests`
- 客户端报连接失败：先确认服务端进程仍在运行，再检查端口 `9000`
- 客户端报“没有发现可用服务实例”：先确认 ZooKeeper 已启动、服务端已成功注册到 ZooKeeper
- JSON 模式调用失败：先确认客户端和服务端的 `rpc.serializer` 配置一致

详细问题请看《故障排查及解决文档》。
