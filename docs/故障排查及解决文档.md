# Mini RPC 故障排查及解决文档

## 1. 文档目标

本文件只负责“出问题后怎么快速定位并恢复”。  
重点是排障路径和可执行动作，不重复架构和部署内容。

## 2. 排障总原则

- 先分层，再定位：网络层 → 协议层 → 业务层
- 先复现，再修复：先稳定复现再改代码
- 先证据，再结论：日志、端口、请求 ID 三方对齐

## 3. 通用排障流程

1. 明确现象：超时、连接失败、反序列化异常、业务报错  
2. 检查服务端是否启动、端口是否监听  
3. 用 requestId 串联客户端与服务端日志  
4. 判断失败层级并执行对应修复  
5. 回归验证：同一请求路径再次执行并确认恢复

## 4. 常见问题与解决方案

### 4.1 客户端连接失败

现象：

- Connection refused
- Connect timeout

排查：

- 服务端进程是否启动
- 目标 IP/端口是否正确
- 本机防火墙或代理是否拦截

解决：

- 启动服务端并确认监听端口
- 修正地址配置
- 临时关闭拦截规则后重试

### 4.2 请求超时

现象：

- 调用长时间无响应后超时

排查：

- 服务端是否收到请求
- 服务端业务执行是否阻塞
- 客户端超时阈值是否过短

解决：

- 优化阻塞逻辑或改异步处理
- 合理提高超时阈值
- 增加请求耗时日志用于后续分析

### 4.3 编解码或反序列化失败

现象：

- 解码异常
- ClassCastException
- 序列化字段不匹配

排查：

- 客户端和服务端协议版本是否一致
- 序列化实现是否一致
- RpcRequest/RpcResponse 字段是否变更

解决：

- 统一版本和序列化策略
- 恢复兼容字段或补充版本适配逻辑

### 4.4 业务执行异常

现象：

- 服务端抛业务异常
- 客户端收到 error 字段

排查：

- 服务实现是否空指针、参数不合法
- 方法路由是否命中错误实现

解决：

- 修复业务实现与参数校验
- 明确异常映射，返回可追踪错误信息

## 5. 快速排障命令（Windows PowerShell）

查看端口监听：

```bash
netstat -ano | findstr :8080
```

查看 Java 进程：

```bash
jps -l
```

## 6. 预防性措施

- 统一日志格式，强制输出 requestId
- 每次协议变更同步更新《变更日志》
- 每个阶段保留最小可运行 demo 回归
- 增加超时、失败率、平均耗时基础指标

## 7. 文档维护要求

- 每出现一次新故障，补一条“现象-定位-解决-预防”
- 每次修复后更新对应版本号和影响范围
- 与《变更日志》互相引用，避免信息断层
